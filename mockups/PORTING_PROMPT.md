# DualCamera — перенос интерфейса из веб-мокапа в нативное SwiftUI-приложение

> Этот файл — самодостаточный промт для новой сессии. Прикрепи/вставь его целиком,
> и агент сможет продолжить работу без истории текущего чата.

## 0. Роль и задача

Ты помогаешь перенести готовый дизайн камера-интерфейса из интерактивного веб-мокапа
в нативное iOS-приложение (SwiftUI, AVFoundation). Мокап считается **источником истины**
по вёрстке и поведению. Приложение уже существует и работает — его нельзя ломать.

Окружение: Windows-машина с исходниками, **сборки и запуск на устройстве выполняет
пользователь в Xcode на Mac**. Агент правит код и не может компилировать iOS-проект,
поэтому изменения должны быть аккуратными, полными и без «полу-рефакторингов».

## 1. Источники истины

- `mockups/index.html` — интерактивный мокап (вёрстка + поведение), ~2900 строк.
  **Все иконки в нём — встроенный SVG-код**, отдельных файлов он не подключает.
  В нём уже реализованы все состояния: сплит/PiP, варианты, зум, палитра рисования,
  меню фильтров, шторка настроек, поворот интерфейса.
- `DualCamera/Views/ContentView.swift` — текущий экран камеры (683 строки),
  содержит рабочий превью-стек и **временные отладочные переключатели**, которые
  нужно заменить новым HUD.
- `DualCamera/Models/CameraManager.swift` (1452 строки) — сессия, две камеры,
  зум, фонарик, фокус, запись, фото, импорт, раскладки.
- `DualCamera/Views/DrawingCanvas.swift`, `Models/DrawingEngine.swift`,
  `DrawingRenderer.swift` — рисование и его встраивание в запись.
- `DualCamera/Models/RealtimeCompositeRecorder.swift`,
  `DualCameraVideoCompositor.swift`, `VideoMerger.swift`, `PhotoMerger.swift`,
  `CaptureLayout.swift`, `PipShape.swift` — композитинг/склейка/раскладки.
- `DualCamera/pointing-up.svg`, `DualCamera/filter.svg`, `DualCamera/flashlight.svg` —

```
drawingTools    34×34 (глиф 19), drawingColors 30×30
filterLabel     шрифт 11, фон rgba(0,0,0,0.56), radius 12
```

Общие правила кнопок:
- тонкие линии, круглые или скруглённые, подложка `glass` (opacity 0.3), без тени и без blur;
- активная кнопка: цвет `yellow`, рамка `activeBorder`, фон `activeFill`;
- disabled/скрытые: `hidden` (не занимает места);
- при повороте в ландшафт кнопки остаются на местах, но **иконки плавно поворачиваются
  на 90°** (transition 240 ms);
- элементы появляются с анимацией (появление/исчезновение блоков — fade + scale).

## 3. Структура экрана

Портрет, сверху вниз:
1. **Верхняя тёмная полоса** (`ink`, без градиента) с «островом» по центру.
2. **Основное поле** — превью основной камеры, по ширине экрана, между полосами.
3. **Нижняя тёмная полоса** (`ink`, без градиента) с кнопками съёмки.

Поверх поля:
- слева сверху-по-центру (ближе к вертикальной середине) — **две колонки блоков** кнопок;
- справа аналогично — **две колонки блоков**;
- справа сверху — шестерёнка настроек;
- снизу поля — зум (дискретные значения + долгое нажатие → ползунок);
- внизу активной камеры — подпись активного фильтра.

## 4. Спецификация элементов

### 4.1 Полосы
- Верхняя и нижняя — сплошной `ink`, без градиента (градиенты были убраны).

### 4.2 Левая колонка (выровнена по вертикальному центру)
Блок 1 — переключатель режима:
- «Сплит»: квадрат, разделённый горизонтальной линией;
- «PiP»: квадрат + залитый квадратик в левом верхнем углу с отступом.

Блок 2 — варианты текущего режима (меняется при смене режима):
- варианты сплита: «сверху/снизу» (квадрат, залита верхняя половина, разделительная линия)
  и «слева/справа» (квадрат, залита левая/правая часть);
- варианты PiP: круг, квадрат, прямоугольник.
- **Кнопки внутри блока центрированы по вертикали и горизонтали.**

### 4.3 Правая колонка
Блок 1 (сверху вниз):
1. «Вставить фото» — иконка картинки;
2. «Рисунок» — карандаш; при нажатии сверху экрана появляется палитра рисования;
3. «Указатель» — контурная рука (встроенный SVG, см. раздел 5); на экран в центр
   ставится маркер-указатель (тот же SVG), который можно перетаскивать;
4. «Фильтры» — три окружности (встроенный SVG, см. раздел 5); открывает вертикальную
   панель фильтров.

Блок 2:
- «Добавить/убрать вторую камеру» — две наложенные рамки (PiP). Полностью скрывает
  вторую камеру во всех режимах.

### 4.4 Нижняя полоса (слева направо)
1. **Фронтальная подсветка** (46) — экран/вспышка фронтальной камеры;
2. **Фонарик** (46) — корпус фонарика (встроенный SVG, без лучей), активный = жёлтый;
3. **Запись** (76) — старт/стоп видео, внутренний красный круг;
4. **Смена камер местами** (46) — две круговые стрелки, работает во всех режимах;
5. **Фото** (46) — фотоаппарат, меньше кнопки записи.

Во время записи показывается таймер и кнопка «стоп» вместо кнопки фото.

### 4.5 Зум
- Дискретные значения: только `0,5` и `1×`, без подложки, стоят близко друг к другу.
- Долгое нажатие на область значений → поверх появляется ползунок:
  слева «−», справа «+», над ползунком значение с точностью 0,1, диапазон 0,5…5.
- Значение, на котором пользователь остановился, остаётся вместо `1×`,
  ползунок исчезает.

### 4.6 Палитра рисования (появляется сверху, по центру)
- Инструменты: кисть, прямоугольник, стрелка, выбор (4 кнопки).
- Цвета: белый, чёрный, красный, синий, зелёный, жёлтый (6).
- Ползунок толщины 2…20 + числовое значение.
- Кнопки: «Отменить», «Очистить».
- Активный инструмент/цвет выделяются.

### 4.7 Меню фильтров
- Панель — **вертикальная лента**, расположена **ниже блока второй камеры**
  справа (выровнена по ширине блока, отступ 8), ширина 48, высота 150.
- Внутри — иконки 38×38: цветок-ромашка (8 лепестков радугой), к иконке применён
  визуальный фильтр, который она представляет.
- Активная зона — **центр панели по вертикали**; при скролле фильтр применяется
  к **активной камере** (по умолчанию — основная, т.е. большая область).
- При открытии по центру встаёт «Оригинал» (без фильтра).
- Снизу активной камеры появляется **название фильтра** (не под каруселью!).
- У нижнего края панели — градиентная подсказка о листании; исчезает в конце списка.
- Список: Оригинал, Яркий, Яркий тёплый, Яркий прохладный, Эффектный,
  Эффектный тёплый, Серебряный, Чёрно-белый, Нуар.
- Иконка «Оригинал» — чистые, немидитированные радужные цвета.

### 4.8 Шторка настроек (шестерёнка справа сверху)
- Формат кадра: 9:16 (по умолчанию), 4:3, 1:1.
- Режим видео: 720p, 1080p (по умолчанию), 4K.
- Частота кадров: 30 (по умолчанию), 24, 60 FPS.
- Качество звука: AAC (по умолчанию), Apple Lossless.
- Тумблеры: Стабилизация (вкл), Телесуфлёр (выкл), Дата и время на экране (выкл),
  Показать сетку (выкл), Тактильная отдача (вкл).
- Стиль: нижняя шторка, скруглённые группы, активный вариант — жёлтый.

### 4.9 Сплит / PiP взаимодействия
- Сплит: перетаскиванием границы меняется соотношение зон (одна больше, другая меньше);
  граница ограничена (в мокапе 25…75 %).
- PiP: окно перетаскивается по экрану, форма переключается (круг/квадрат/прямоугольник).
- Смена камер местами и скрытие второй камеры работают во всех режимах и анимируются.

### 4.10 Маркеры
- Указатель — встроенный SVG-маркер (та же геометрия руки) добавляется в центр поля
  и перетаскивается.
- Цвет маркера задаётся из палитры (через `color` + CSS-фильтр).

- **Иконки в мокапе — это не файлы, а встроенный SVG-код прямо в `mockups/index.html`.**
  Отдельные файлы `DualCamera/*.svg` существуют, но мокап на них **не ссылается**
  (в нём нет ни одного `src="*.svg"`); они лежат как исходники геометрии.

## 5. Ассеты и иконки

Реально используется в мокапе (inline SVG внутри HTML):

| Кнопка | Где в разметке | Геометрия (canvas 288×288) | Толщина в мокапе |
|---|---|---|---|
| «Указатель» | кнопка `[data-mark="pointer"]` + маркер `#canvasMark` | контурная рука, `M103 25 … Z` + 5 коротких штрихов | `1.55` |
| «Фильтры» | кнопка `#filterButton` | группа `scale(1.3090909)`: круг `cx=110 cy=80 r=38` + две дуги `A38 38` | `1.55` |
| «Фонарик» | кнопка `#torchButton` | корпус фонарика (без лучей) | `0.5` (заливка) |

- Все inline-иконки: `fill="none"`, `stroke="currentColor"` (или заливка для фонарика),
  поэтому цвет берётся из кнопки (белый / жёлтый при активном состоянии).
- Глобально в CSS стоит `svg * { vector-effect: non-scaling-stroke; }`, поэтому
  `stroke-width` = толщина в CSS-пикселях независимо от `viewBox` и трансформаций.
  Отсюда в мокапе используется `1.55` (как у остальных иконок HUD).
- Файлы `DualCamera/pointing-up.svg` и `DualCamera/filter.svg` содержат ту же геометрию,
  но в «сыром» виде: `viewBox="0 0 288 288"`, `stroke-width="5"` (рука) и
  `stroke-width="4"` при `scale(1.3090909)` (фильтр). Это версии для переноса в приложение;
  мокап их не подключает.
- Для нативного приложения: либо добавить эти SVG в `Assets.xcassets` (Preserve Vector Data,
  Single Scale) и рендерить как `.template` (цвет через `foregroundStyle`), либо нарисовать
  те же `Path` в Swift. В обоих случаях визуальная толщина должна быть **1.55 pt** при иконке 21×21
  (для 288-canvas это соответствует `stroke ≈ 21` единиц, поэтому «5» из файла нужно
  привести к целевому размеру).
- Остальные иконки HUD — SF Symbols или `Path`, **толщина линий 1.55 pt**, визуально
  совпадает с SVG-иконками.
- Иконки в ландшафте поворачиваются на 90° (сама кнопка остаётся на месте).

## 6. Что уже есть в Swift / чего нет

Есть:
- две камеры (back/front), превью-слой и кадровый fallback;
- `layout` (`.splitScreen`, `.pip`), `splitOrientation`, `pipShape`;
- зум `setZoom`, `min/maxZoomFactor`, фонарик `toggleTorch`, `hasTorch`;
- фокус/экспозиция по тапу; запись (в т.ч. realtime-композитинг), фото, склейка;
- импорт фото/видео и оверлей поверх превью;
- рисование (`DrawingEngine`, `DrawingCanvas`, рендер в запись);
- PiP-перетаскивание через `updatePipOffsetFraction`.

Нет (нужно создать):
- новый HUD (сейчас вместо него отладочные пикеры, A/B-кнопки и «эксперимент записи»);
- перетаскиваемая **граница сплита** (сейчас фиксированные 50/50);
- **фильтры** (CoreImage-пайплайн для превью + записи + фото);
- настройки: формат кадра (9:16/4:3/1:1), разрешение, FPS, качество аудио,
  стабилизация, сетка, дата/время на экране, телесуфлёр, тактильная отдача;
- **фронтальная подсветка** (заливка экрана) как отдельная кнопка;
- карусель фильтров и подпись фильтра;
- длинный пресс на зум → ползунок 0,5…5 с сохранением значения;
- маркер-указатель на превью.

## 7. Стратегия переноса

1. **HUD отдельно от логики.** Всё новое — в `DualCamera/Views/HUD/`:
   - `HUDTheme.swift` — токены (цвета, размеры, шрифты, анимации);
   - `HUDButtonStyles.swift` — стили круглых кнопок и активных состояний;
   - `TopControlsView.swift` — левая и правая колонки;
   - `CaptureBarView.swift` — нижняя полоса;
   - `ZoomControlView.swift` — пресеты + long-press ползунок;
   - `DrawingPaletteView.swift` — палитра рисования;
   - `FilterCarouselView.swift` — вертикальная лента + подпись;
   - `HUDOverlayView.swift` — сборка слоёв поверх превью;
   - `SettingsSheetView.swift` — шторка настроек.
2. **Состояние.** `CameraManager` остаётся владельцем захвата. Настройки и UI-состояние —
   в отдельных `@Observable` моделях (`CameraSettings`, `HUDState`), которые прокидываются
   в HUD и применяются к `CameraManager` через явные методы.
3. **Раскладка.** Точные размеры в pt по токенам; общий контейнер `GeometryReader`
   + `safeAreaInsets`, чтобы совпадало с мокапом на 390-pt ширине и корректно
   масштабировалось на других устройствах.
4. **Порядок работ.** Сначала «внешность» (полосы, кнопки, состояния) без новой
   функциональности, затем интерактив, затем новые возможности (фильтры, настройки,
   подсветки, зум-ползунок). Каждый этап — отдельный проверяемый инкремент.
5. **Совместимость.** Отладочные переключатели (`A/B превью`, `realtime`) убрать
   из продукта, при необходимости спрятать под `#if DEBUG`.
6. **Запись/склейка.** Любые изменения превью не должны менять формат итогового файла,
   пока явно не реализован соответствующий этап.

## 8. План по этапам (с критериями приёмки)

**Этап 0. Подготовка**
- Ветка `feature/new-hud`, скриншоты мокапа (портрет/ландшафт) как референс.
- Убрать/спрятать отладочные элементы, чтобы HUD собирался с чистого экрана.
- Приёмка: проект собирается, прежняя функциональность доступна.

**Этап 1. Каркас HUD**
- Полосы (без градиента), безопасные зоны, колонки слева/справа по центру,
  шестерёнка, нижняя полоса.
- Приёмка: визуально совпадает с мокапом в портрете; ландшафт — иконки повёрнуты на 90°.

**Этап 2. Кнопки и состояния (без новой логики)**
- Режимы, варианты сплита/PiP, инструменты, вторая камера, нижняя панель, зум-пресеты.
- Приёмка: нажатия меняют состояние и цвет (жёлтый), блоки вариантов появляются/исчезают
  с анимацией, кнопки в блоках центрированы.

**Этап 3. Интерактив раскладок**
- Перетаскивание границы сплита (25…75 %), PiP-перетаскивание, смена камер, скрытие
  второй камеры — с анимациями; всё синхронно с записью/фото.
- Приёмка: превью и итоговый файл совпадают по геометрии.

**Этап 4. Палитра рисования**
- Новый вид палитры, связанный с `DrawingEngine` (инструменты, 6 цветов, толщина,
  undo, clear). Появление сверху с анимацией.
- Приёмка: рисунок попадает в запись/фото как раньше.

**Этап 5. Фильтры**
- `VideoFilter` (9 значений) + CoreImage-пайплайн для превью; применение к активной камере;
  вертикальная карусель с активной зоной и подписью снизу активной камеры.
- Затем — те же фильтры в записи и фото.
- Приёмка: превью и файл выглядят одинаково, подпись фильтра на месте.

**Этап 6. Настройки**
- Шторка + применение: формат кадра, разрешение, FPS, качество аудио, стабилизация,
  сетка, дата/время, телесуфлёр, тактильная отдача.
- Приёмка: значения реально влияют на сессию/запись, сохраняются между запусками.

**Этап 7. Зум, подсветки, маркер**
- Long-press ползунок 0,5…5 с «−/+» и сохранением значения; фронтальная подсветка;
  фонарик с новой иконкой; маркер-указатель с перетаскиванием.
- Приёмка: все элементы соответствуют мокапу, жесты не конфликтуют.

**Этап 8. Полировка**
- Анимации, хаптика, доступность (labels/hints), проверка на маленьких экранах
  и в ландшафте, чистка кода.

## 9. Правила работы

- Не ломать существующие сценарии: фото, видео, realtime-запись, импорт, склейка.
- Не менять формат/логику склейки без явной задачи.
- Новые файлы — в `Views/HUD/`, модели — в `Models/`.
- Все размеры/цвета — через `HUDTheme`, без «магических» чисел по месту.
- Комментарии — только там, где нужно пояснение.
- Проверка: пользователь собирает в Xcode; перед передачей изменений — самопроверка
